# 设计边界

team-workflow 统一团队交付下限：原始目标和验收条件、同一知识入口、实际检查结果、最终审查、任务经验回写。实现步骤保持可选择。项目不复制通用脚本，升级集中发布的插件；只有项目契约或真实检查发生变化时修改项目配置。

知识通过独立 CS 读取。`wiki.documents` 是原文导航登记，不另建知识库。词汇和设计决策由 MATT 原生格式文档拥有正文，CS 读取当前文件并提供范围、状态、哈希和摘录。CS 经验卡片只维护原文未覆盖的稳定结论。原文重命名保留登记编号；重复卡片通过引用和取代关系保留历史，不能静默删除或批量判定矛盾。

MATT 方法来自固定上游文件，不维护一套重写的方法摘要。15 个技能的同级目录以 `matt-` 区分，按当前任务加载。局部适配统一知识读取、完整工作区审查和授权边界；保留原版方法、模板、示例和术语。CS 自身不增加阶段、验收关卡或任务路由。

工具把执行和核查分开。执行器以 argv 调用项目命令，采集 Go JSON、JUnit 或普通命令结果。核查器只读，对比工作区、配置、任务、工具、原文和知识版本，拒绝必要用例缺失、跳过、失败、零用例、过期结果和未完成 CS 任务。评审逐项对应需求和验收，不能由模板自动生成通过结论。

跨仓由参与仓库各自保存任务与验证；同一任务编号连接它们，联合检查绑定所有参与仓库。权威知识可跨仓引用，但不会从其他工作区猜测一个历史提交的知识版本。环境和原始证据留在业务仓库，公开插件只带通用契约。

版本 0.3.0 延续第二版数据合同与第一版只读材料检查。CS 2.1.0 仍使用格式 4，只增加可选原文登记和引用项。升级技能不触发知识重建。检索顺序、命令退出成功、作者声明和本地哈希都不能单独替代业务事实判断。
