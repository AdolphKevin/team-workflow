# 设计边界

团队统一共享信息和完成条件，个人选择模型、工具、规划和开发方法。工作流按开始、必要交接、交付提供约定，通用能力集中发行，项目只保留必要配置与业务测试。

项目规则、术语和决策只有一份登记原文，通过独立 CS 的 brief/documents 读取；已有经验从同一入口检索。任务平台维护进行中的需求、职责、进度与问题。CS 完成记录只保留紧凑结果、依据与独立经验，不复制规格、进度或原文。

MATT 方法直接复用锁定的源码、模板与配套资源。适配入口承载团队约定，知识与协作能力不复制为另一套开发方法。CS 本身不增加任务调度、阶段或验收关卡。

GitHub 读取器只执行 GET。交接工具生成草稿，现有授权决定是否发布。交接评论形成带前序指纹的历史，冲突明确保留；需求指纹与进度分离。可接续与交付完成是两个不同结论。

本地执行继续支持第二版完整工作区绑定。第三版可移植结果在执行时记录仓库身份、提交、内容、检查定义、环境和原始报告；GitHub 适配器核对来源并重解码原始报告。远端成功或本地摘要不能单独证明业务验收。

跨仓任务可用不同编号，但关联同一总任务。可移植联合清单使用仓库标识和版本，调用方单独提供本机目录映射；联合运行必须覆盖所有参与仓及公共依赖。未共享改动、本机外部文件和缺失证据准确留下缺口。

版本升级不重建知识，不自动改变在途任务所用插件。旧格式仍在旧语义下读取；新字段、当前要求或来源核查缺失时不能伪装成新版完成证明。
