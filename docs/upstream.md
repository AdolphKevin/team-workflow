# MATT 来源与更新

基线是 [mattpocock/skills](https://github.com/mattpocock/skills) 主分支提交 `b0618bc436ad893b3c5e84e55fba86586d34a404`。它比 v1.3.1 多 44 个尚未发行的提交，没有发行标签指向它，因此锁文件记录为 `main@b0618bc`。许可完整保留在 `licenses/MATT-MIT.txt`。

## 锁文件与补丁

`upstream/matt.lock.json` 逐文件记录原路径、原文哈希、发行路径和本地哈希；`upstream/matt.patch` 是完整的最小差异。

`scripts/check_release.py` 在隔离目录反向应用差异，核对恢复出的每份上游文件哈希，并核对锁文件的版本说明与提交一致。整个过程无需联网，也不依赖个人插件缓存或上游安装。

## 复用的方法

复用的方法包括：规格、任务拆分、实现、依赖任务实施、诊断、测试先行、模块设计、领域建模、双维度审查、复盘、问题澄清、PR 描述、原型、面向代理写作和研究。配套模板、测试例子、设计说明与脚本都随所属技能保留。

## 本地适配

- 技能改名为 `matt-*`，内部引用随之更新。
- 统一从 team-knowledge 读取项目知识（`tw brief`、`tw read`）。
- 词汇表与 ADR：项目有已登记原文时改原文，否则写在 `.tw/glossary.md` 与 `.tw/decisions/`，文件按日期加 slug 命名，不用顺序编号，避免并行分支撞号。
- 已有授权延续，多代理可选，审查覆盖完整工作区，验证按风险要求进行。
- 规格、任务拆分、实现、依赖任务实施和复盘五个方法保持上游的“只允许显式调用”。
- 环境复盘只保留环境分析方法。
- 不新增自动提交或外部发布行为。

## 更新上游

1. 在临时目录取得明确的提交，比较上游变更。
2. 重新应用本地适配，更新锁文件和差异。
3. 验证所有内部链接、上游哈希、测试，并做独立技能试用。
4. 发布新版本，保留被替代版本的标签。
