# 0.4 验收标准

| 范围 | 通过条件 |
| --- | --- |
| 任务接续 | 当前要求、负责人、可获取代码、已验证范围、问题责任和下一步均可读取；并行交接、被编辑前序和过期要求明确报告 |
| 跨服务 | 各仓任务关联一个总任务；职责、接口原文与确认、依赖交付及联合负责人齐备；公共依赖版本不能遗漏 |
| 结果导入 | 真实执行时采集的结果与平台 run/job/attempt/artifact 对应；旧批次、失败、跳过必要用例、零用例、缺少来源或报告不能通过 |
| 联合验收 | 所有参与方和公共依赖对应相同版本；本机目录变化不影响身份；未共享改动与无法取得证据保留为缺口 |
| 知识 | CS 一次读取原文与经验；原文变化识别旧引用；同一任务幂等更新，无新独立结论只记录结果 |
| 直接复用 | 15 个 MATT 技能、41 份源文件和许可可追溯；反向补丁逐文件匹配上游 |
| 集中维护 | 同一发行包在 Codex、Cursor 加载；业务仓没有通用脚本副本；第二版配置继续使用 |
| 自由选择 | 简单任务无需长规格、测试先行或多代理，方法与交付结论分开 |

工程验证运行工作流行为测试、锁定 CS 的真实接口测试、发行与来源校验，覆盖 Python 3.10/3.13。技能改动还在隔离工作区用真实原始任务进行独立代理试用。

真实试点采用 LiveChat Core→Gateway 频道授权链路，使用真实 Core 接口、Gateway 订阅入口及测试数据库，核对合法订阅、越权拒绝、权限变化后的再次授权，以及 Core 不可用时拒绝新的授权。记录 Core、Gateway、common 的真实版本和未提交变化。业务原始材料只保留在其项目权限范围内。

正式发布要求两名成员分别使用 Codex、Cursor，在不读旧聊天、不接受口头补充的情况下双向接续实际任务；下一次相关任务能找到并正确使用先前经验。单个操作者运行两种真实工具可证明跨工具能力，不能替代两名成员试点。未满足正式条件仅发布候选版，并列明缺口。
