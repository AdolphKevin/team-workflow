# 0.3.0 验收标准

| 范围 | 通过条件 | 验证方式 |
| --- | --- | --- |
| 独立仓库 | 独立 Git 历史；公开发行不包含业务知识、个人路径或试点原始材料 | 干净检出、发行扫描、GitHub 仓库核对 |
| MATT 复用 | 15 个原技能、41 份源文件及许可可追溯，依赖链接可达 | 反向应用补丁并逐文件比对上游哈希 |
| 单一知识入口 | CS 一次简报返回相关原文和经验，全文从同一入口读取 | 真实 CS 接口测试 |
| 知识不重复 | 当前引用无复制正文；旧卡片与来源关系保留 | CS 替代/引用/幂等回归 |
| 版本有效性 | 原文、工作区、任务、配置或工具变化后旧证据不能通过 | 负向回归、跨仓原文变更 |
| 实际验证 | 必要测试失败、跳过、零用例、缺失、超时或环境不足明确失败 | Go、JUnit、普通命令行为测试 |
| 最终审查 | Standards 与 Spec 分别有证据，每项验收均对应审查 | 工作区审查与模板负例 |
| CS 闭环 | 同一任务已完成，引用与原文健康，无新结论允许只写任务 | 真实 bootstrap/brief/learn/doctor/verify |
| 跨仓验收 | 所有参与仓完成且联合测试对应相同版本 | 聚合回归及实际项目试点 |
| 集中升级 | 通用脚本只在插件内，项目保留声明配置 | 发行包、接入配置检查 |

发布工程检查运行 `scripts/check_release.py`；执行测试运行 `scripts/test.py`；独立 CS
接口试验运行 `scripts/check_cs.py`。结果在实际运行后记录，不能把文件存在或生成模板算作通过。

真实团队验收另外要求：至少一个实际跨服务业务任务完成必要环境验证，两名成员
各自通过技能完成实际开发，结果达到同一验收下限。隔离代理试用、已有单元测试及
配置接入可以证明工具可用，不能替代上述真实业务与人员试点。未完成时明确保留为待验收。
