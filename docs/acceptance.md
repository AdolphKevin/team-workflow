# 知识库验收标准

本仓的当前依据是[已批准方案](proposals/2026-10-22-knowledge-only.md)与[知识库场景](sop/tw-knowledge-only.yaml)。由未参与实现的独立代理，在仓库外的临时项目和临时技能目录中，经实际命令入口操作并留证；预期来自场景的 expected 与 forbidden_effects。

| 场景 | 核对结果 |
| --- | --- |
| SOP-01 | 初始化、写条目、读取、检查、健康报告与缓存独立可用；选择原因正确；跨仓原文可读；失效的测试名报错 |
| SOP-02 | 旧项目知识可用；每个旧团队字段给迁移提示；配置与本机材料不变；旧团队命令明确退出且零写入 |
| SOP-03 | 发行检查与打包通过；只含知识技能与公开文档；安装完整性及版本一致；公开文本没有内部信息 |
| SOP-04 | 其他开发流程中的代理在改代码前读取知识，完成后按实际需要维护知识并检查；拼写修正不强制新增知识 |
| SOP-05 | 本仓知识检查零错误；受删除影响的条目逐个处理；现行入口与职责一致 |
| SOP-06 | 按升级说明整理旧场景后可由 sop-board 校验，人工范围的原因、负责人和触发时机保留 |
| SOP-07 | 按来源移除旧技能与团队指引；成员自有技能、自写内容和知识原样保留 |

## 执行与证据

1. 在临时目录复制最终候选内容，保存文件清单和摘要；未提交版本以工作区摘要标识。准备临时 Git 项目、共享仓、旧版项目与技能安装目录，实际账号和成员安装目录不参与。
2. 逐场景记录命令、输入、完整输出、退出码、操作前后数据与文件摘要。失败保留首次输出，修复后由独立执行者复验受影响的场景。
3. 技能试用使用独立会话与原始需求，记录实际读取、调用与最终文件；仅模拟技能加载条件时明确写出差异。
4. 结果写入[验证记录](validation.md)，列出执行者、环境、版本摘要、证据位置、通过、失败、受阻与未执行范围。开发者自检、独立验收与真实成员试点分别记录。

本仓不新增单元、接口或集成测试。发行前运行 `python3 scripts/check_release.py` 与 `python3 scripts/package.py --output <仓库外>/tw.zip`；CI 在 Python 3.10、3.13 上执行这两步。本机运行不等于 CI 已验证。`docs/sop/archive/` 是旧场景，仅供历史追溯与迁移练习。

两位真实团队成员各自在自己的工作流中试用一周，记录 brief 是否找到相关约束、放弃原因是否避免重复错误。缺少成员试点或真实执行证据时，在验证记录中保留未完成状态。
