# 成员操作说明：项目知识

项目知识放在各仓库的 `.tw/`，与代码一起评审。知识的读取和更新与使用的开发流程无关。格式见[写作规范](../skills/team-knowledge/references/writing.md)。

命令中的 `tw` 为 PATH 上的启动器，安装方法见[安装说明](install.md#安装知识技能)；也可用 `python3 <team-knowledge 技能目录>/scripts/tw.py`。

## 日常使用

开工前用 `tw brief --task "<原始要求>" --path <相关路径>` 读取约束、决策和教训；需要全文时用 `tw read <条目>`。出现曾放弃的方向时，先核对原因，再决定是否有新理由。

完成后记录可复用的结论：改变必须保持的行为时写规则，作出需要背景才能理解的选择时写决策，解决根因不明显的缺陷时写教训，标题写成一句要遵守的做法。又遇到已有教训或规则所述的问题，或照它做对了，在该条目追加出现记录或做对的例子。没有长期结论的小改动只需说明理由。已有原文直接更新原文，最后运行 `tw check`。

评审代码改动时，用改动的文件作 `--path` 读取，逐条核对其中的规则，评审意见写明不满足哪一条。

工作区接入按快照判断产品变化的验收看板时，`.tw/` 的修改会计入产品变化。由用户选择：在看板中把 `.tw/` 排除在产品快照之外；或在验收轮次进行中把知识草稿写在 `.tw/local/<任务>/`，轮次结束后与代码一起提交。

## 复盘与升级

每个项目按自己的节奏复盘，例如每周一次，或交给定时运行的代理。在会话中提出“复盘最近一周的提交”，代理按[复盘与找回教训](../skills/team-knowledge/references/lessons-from-history.md)回看提交，找返工、不该合入、验证太粗三类问题：同一失败机制追加出现记录，新机制写成教训，做对的提交写进做对的例子。结果是一个只改知识的 PR，说明写明范围与证据；下一次从该 PR 写明的终点继续。

`tw audit` 的“反复出现”一节列出出现 2 次以上的条目。教训满 3 个不同日期时 `tw check` 提示升级，按[写作规范](../skills/team-knowledge/references/writing.md#出现与升级)移到 `rules/`。升级把经验定为团队的硬规则，由用户在 PR 中确认，之后的评审逐条核对。

参考 magpie 错题本时，一条教训与 tw 条目的对应：

| magpie | tw |
| --- | --- |
| `**<一句话规则>**` | `title` 与正文首行 |
| 哪个提交或 Issue 出的事、后果 | 正文“现象”，复发写进出现记录 |
| 修复的提交 | `source` 与“修复与防护” |
| `Done right: <做对的例子>` | `## 做对的例子` |
| `Seen N× (YYYY-MM-DD, …)` | 由出现记录计算，`brief` 显示“出现 N 次” |

验收看板每周质量复盘中的“同类缺陷再次出现”，也按上述方式记到对应教训。

## 评审知识改动

1. 对照业务要求与实际入口判断结论是否成立；结构检查通过不能替代判断。
2. 核对作用范围、来源与防护引用。`guards` 写成 `仓库:文件#测试名`，引用只表示可追溯，运行由 CI 证明。
3. 改变决策时保留旧做法和放弃原因。一次性结果、测试计数、工具版本、行号和任务过程写入变更说明。
4. 跨仓事实写在契约提供方，其他仓通过 `related` 引用。
5. 追加出现记录或升级为规则时，核对每项日期与所引证据确有其事；升级后的规则保留出现记录。

## 本机材料与清理

`.tw/local/` 被 Git 忽略，按检出目录隔离。`cache/` 是可重新生成的查询缓存，`repositories.json` 是本机共享仓路径映射，其余材料由成员维护。`tw audit --top 10` 按顶层项列出大小、文件数和最后修改时间，标出 30 天以上未修改的材料，供成员决定清理范围；`tw cache --clear` 只清理缓存。

整目录删除或 `git clean -fdx` 会丢失映射与成员保存的原始材料。需要清理时先备份有用材料，核对删除范围；知识条目和 `config.json` 保留。升级不会自动清理本机目录。

共享仓默认路径写在 `${XDG_CONFIG_HOME:-~/.config}/tw/repositories.json`：

```json
{"projects": {"github.com/acme/core": {"repositories": {"common": "~/src/common"}}}}
```

检出目录覆盖写在 `.tw/local/repositories.json`：

```json
{"repositories": {"common": "../common"}}
```

命令行 `--repository common=<路径>` 优先，其次是检出目录、用户级配置；按别名逐项覆盖。工具只读映射，不猜测路径或克隆仓库。

## 初始化、升级与历史

新项目先 `tw init` 预览，再 `tw init --apply --guidance` 写入，填写生成的概览。旧知识目录按[迁移指南](../skills/team-knowledge/references/migration.md)逐条核实；已采用 `.tw/` 的项目按[升级说明](install.md#从-0x-升级)保留知识。

找回历史教训只在成员要求时进行，候选的支持证据、反证和未核实部分随变更一起评审。
