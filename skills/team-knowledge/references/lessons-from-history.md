# 找回历史教训

只在用户要求时执行，不是迁移或日常任务的默认步骤。

## 来源

- 旧知识的 git 历史：`git log --diff-filter=D --name-only -- .codestable`，以及 `git show <提交>^:<路径>`。
- Issue、PR 和已有的复盘文件，例如 `history-review/`。
- 其他仓库的历史：只迁入适用于本仓实现的教训，并写明适用条件。

## 做法

1. 先列出候选：现象、根因、出处，交给用户确认范围。
2. 只保留现在仍可能再犯的失败机制。逐条阅读当前代码，确认防护是否还在；有守护测试的写进 `guards`。
3. 用 `tw new lesson` 写成教训，`source` 指向原始提交或 Issue，`verified` 写实际核对时的提交。
4. 运行 `tw check`，在 PR 中列出采纳与放弃的候选，由用户确认。
