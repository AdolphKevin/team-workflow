# 团队开发工作流

交付用户需要的结果，并留下对应实际代码的验证依据。本插件直接复用 MATT 技能及配套文件；CS 是独立维护的知识依赖。统一完成条件，按任务选择实现方式。

## 选择任务范围

读取适用的项目规则、`.team-workflow.json` 和当前改动，保留已有用户修改。从当前安装的技能列表发现 CS 目录，再运行 `python3 <本技能目录>/scripts/workflow.py project --root <项目> --cs-skill <CS技能目录>`。首次接入、配置缺口或旧版配置见[接入与升级](references/onboarding.md)。

只读分析、规划或交付核查以结论为交付物：保留项目和原材料；核查命令不代替实现授权。开发任务继续下文。不要为流程自动创建外部任务、提交代码或安装插件。

## 读取知识并确定验收

发现并读取当前安装的 CS 技能，使用其预检、原始请求及实际路径/符号读取简报。按[工具约定](references/contracts.md)保存 `brief` 回执；先读回执中的简报正文，再实现。范围明显变化时补读。CS 不可用时可继续独立开发，但完整验收未完成；普通升级不授权重建知识库。

CS 简报同时读取已登记原文和经验；原文摘录不足时使用 CS `documents read --id`，保持一个知识入口。跨服务通过登记的权威定义索引定位原文。区分已接受规则与当前行为，报告冲突并查证，不静默选择。跨仓方法见[联合验收](references/cross-repository.md)。

复用已有任务或规格，形成一份紧凑任务文件：原始目标、非目标、基准提交、风险、可观察验收项及检查关联。任务平台遵循项目约定。简单文档任务可只做内容核查；持久化、鉴权、并发、消息、公共接口与跨服务风险必须有对应实际检查。检索到风险而任务未声明时先修正任务，不能只按已有标签机械放行。

## 实现与验证

按需直接读取本包 MATT 技能：规格 [matt-to-spec](../matt-to-spec/SKILL.md)、拆分 [matt-to-tickets](../matt-to-tickets/SKILL.md)、实现 [matt-implement](../matt-implement/SKILL.md)、多任务 [matt-implement-spec](../matt-implement-spec/SKILL.md)、诊断 [matt-diagnosing-bugs](../matt-diagnosing-bugs/SKILL.md)、行为测试 [matt-tdd](../matt-tdd/SKILL.md)、模块设计 [matt-codebase-design](../matt-codebase-design/SKILL.md)、术语与决策 [matt-domain-modeling](../matt-domain-modeling/SKILL.md)、审查 [matt-code-review](../matt-code-review/SKILL.md)、复盘 [matt-retro](../matt-retro/SKILL.md)。只加载当前需要的方法，遵循[接入边界](references/matt-integration.md)。测试先行、多代理、长规格和拆分方式按需采用，不构成统一强制顺序。已有选择和授权直接沿用。

按[工具约定](references/contracts.md)运行选定检查。配置真实命令、必要用例、环境与结果格式；业务测试留在业务仓库。普通命令成功只证明命令完成。必要测试失败、跳过、零用例、超时或缺环境时保留缺口。运行工具不承担数据库初始化、数据修复或生产操作授权。

验证绑定完整工作区及任务/配置，包括原有修改、暂存、未暂存、新增和删除文件。代码或验收条件变化后重新执行；不为通过检查而提交代码、缩小范围或删除完成条件。

## 回写与最终评审

业务实现和必要验证稳定后，按 CS 当前规则延续同一逻辑任务，完成 `learn --dry-run`、相同计划应用及 `doctor`；任务记录中包含工作流任务 ID。术语或设计决策更新登记的原文；CS 仅记录来源、变更和新的独立经验，不复制正文。无新长期结论时只写任务记录。流程尚未满足业务验收时只允许未完成记录和空卡片集合。

执行 `knowledge` 捕获 CS 完成状态，再生成 `review-template`。实际评审后填写，不能把模板直接改为通过。分别核对项目约束、需求、所有验收项、风险遗漏和知识冲突；覆盖基准提交到最终文件，以及全部暂存、未暂存和新增内容。评审可由当前代理单独完成，不要求额外代理。

将运行记录和审查对象关联到证据。若 CS 写回改变了规则，复核其对实现和验证的影响；只改知识不会机械作废业务测试。评审后修代码则重新验证、更新任务知识并重新评审。

Python 场景任务保留项目自己的完整证据审查与 `codex-review.json`；运行成功不能替代该审查，生产运行时不得调用本技能或审查代理。

## 交付

执行只读 `verify`；多仓任务还需 `aggregate`。缺少运行记录、最终评审、CS 完成状态或联合验证时，准确报告未完成及缺口。第一版 `check.py` 仍只核对材料，不接受为第二版执行证明。

完成回复说明实际行为、验证范围、对应工作区与知识处置。工具的成功表示所列本地流程检查完成，不是全部业务正确或防伪证明。用户跳过必要环节时尊重选择，并保留无法验证的结论。
