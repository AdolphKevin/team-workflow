# MATT 方法在团队工作流中的边界

这里的技能直接来自锁定的 MATT 1.3.1 源文件和配套模板。方法按任务选择；团队统一的是知识入口、完成标准和实际验证。测试先行、细分任务、原型和多代理均按需要采用。

开始前读取当前安装的独立 CS 技能，通过一次 `brief` 同时取得登记原文和经验。词汇表、决策和项目规则的正文只保存在 `wiki.documents` 指向的原文件；摘录不足时用 CS `documents read --id` 读取全文。不要再搜索另一套知识库来解决冲突，也不要把检索先后当作权威顺序。

领域建模直接编辑登记的 GLOSSARY 或 ADR，沿用本包原有格式。新原文需登记；任务结束后 CS 只记录此次变化、来源和验证。旧重复卡片通过带原文哈希的 reference 和 supersedes 保留历史。新的、原文未覆盖且有证据的经验才形成独立卡片。复盘不再写一份平行的“设计决策知识”。

继续已有任务时沿用范围和授权。规格和任务可以先保留本地草稿；向外部平台发布、提交、开 PR、关闭任务或执行生产操作都遵循用户已有授权。方法本身不额外授予权限，不为通过流程而自动提交代码。

多个代理或工作树有助于当前任务且已获授权时才采用；否则由当前代理完成同样的分析与验收。已明确的方案和测试入口直接沿用，只对影响验收的实质歧义询问。单元测试或内存适配器不能替代项目要求的真实数据库、消息或跨服务验证。

交付通过 team-workflow 的运行记录、已核对来源的外部结果、最终工作区审查和 CS 完成记录核对。审查覆盖暂存、未暂存、新增与已提交内容。保留 Standards（项目约束）和 Spec（用户要求）两项结论；缺失或跳过不能填成通过。命令成功和本地记录一致不等于所有业务行为已被证明。
