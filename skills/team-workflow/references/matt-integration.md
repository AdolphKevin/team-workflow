# MATT 与 CS 接入约定

使用开发方法前，发现已安装的独立 CS 技能，读取其 SKILL.md 和“开发方法与知识归属”，
按 CS 运行只读预检并读取项目知识。CS 未安装、知识初始化未完成或格式不可用时，报告
具体前提；本包不把普通任务、安装或升级解释成初始化或重建授权。用户在当前任务已明确
授权这些工作时继续按该授权完成。

MATT 负责开发方法，CS 统一负责原文、知识读取和同一逻辑任务的最终记录。方法切换不
产生第二条任务记录，原文不复制到经验卡片。知识处理顺序遵循当前任务的验收要求和 CS
约定；第四版团队任务先完成业务验收，再写最终 CS 记录。

独立调用 MATT 保持轻量，不要求 `.team-workflow.json` 或交付报告。从 `team-workflow`
开始的新任务默认进入[团队流程](team-delivery.md)；已进入团队流程后直接调用 MATT，仍
沿用有效方案、批准、评审方式和交接责任。旧格式任务按原规则继续，显式切换才采用新版。

保留用户已选方法、实现方式与已有授权。简单任务可实现后合并评审，风险决定检查；中等、
复杂任务获批且指派后直接实施。普通 MATT 的提问或旧阶段文档不能重新要求已经完成的
确认。方案实质变化按[分节方案约定](designs.md)处理，分工和普通进度不使批准失效。

测试先行、多代理和独立目录按需要采用。提交、发布、开 PR、关闭任务和生产操作沿用
已有授权，工具生成草稿不新增外部操作权限。验证必须满足实际风险和项目要求。
