# 方法与知识约定

使用任何开发方法前，用 team-knowledge 读取项目知识：`tw brief --task "<要求>" --path <相关路径>`。项目缺少 `.tw/` 时，报告这一前提并停在这里；初始化和迁移在用户明确要求时进行。

MATT 负责开发方法，team-knowledge 负责知识。切换方法不产生第二份知识记录。词汇表和决策已有登记原文的，改原文，不复制成条目；知识与代码在同一个改动中更新。团队任务先完成业务验收，再更新知识。

独立调用 MATT 保持轻量，不要求团队配置或交付报告。从 `team-workflow` 开始的新任务默认进入[团队流程](team-delivery.md)；已进入团队流程后再直接调用 MATT，仍沿用有效方案、批准、评审方式和交接责任。

保留用户已选的方法、实现方式和已有授权。简单任务可以实现后合并评审，检查内容由风险决定；中等、复杂任务获批并指派后直接实施。普通 MATT 提问不能重新要求已经完成的确认。方案实质变化时按[分节方案约定](designs.md)处理；分工调整和普通进度不会使批准失效。

测试先行、多代理和独立目录按需要采用。提交、发布、开 PR、关闭任务和生产操作沿用已有授权；工具生成的草稿不新增外部操作权限。验证必须满足实际风险和项目要求。
