# 方法与知识约定

使用任何开发方法前，用 team-knowledge 读取项目知识：`tw brief --task "<要求>" --path <相关路径>`。项目缺少 `.tw/` 时，报告这一前提并停在这里；初始化和迁移在用户明确要求时进行。

MATT 负责开发方法，team-knowledge 负责知识，知识只记在 `.tw/` 一处；词汇表和决策已有登记原文时直接改原文。团队任务先完成业务验收，再在同一个改动中更新知识。

独立调用 MATT 保持轻量，只需要项目知识。从 `team-workflow` 开始的新任务进入[团队流程](team-delivery.md)；团队流程中再调用 MATT 时，沿用有效方案、批准、评审方式和交接责任。

保留用户已选的方法、实现方式和已有授权，已完成的确认继续有效。批准路径见[分节方案](designs.md#内容与依赖)，批准与评审绑定的内容见[记录绑定](contracts.md#记录绑定)。

测试先行、多代理和独立目录按需要采用，验证满足实际风险和项目要求。提交、发布、开 PR、关闭任务和生产操作沿用已有授权，工具与成员的分工见[工具做什么](contracts.md#工具做什么)。
